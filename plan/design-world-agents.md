# The speaking furniture of Millrace

A book with no conversation mark opens a screen. A book with a little brass ear can be asked a question. In the directory the distinction is spelled out: **Open My invoices** and **Ask Counterfoil**. NPCs are local specialists a person addresses deliberately. The town does not send a model a prompt every time someone strolls past a desk.

All five use a settled speaking pose plus text in reduced-motion mode. Nearby people see idle machinery. A person's question, record selection, activity indicator and reply are private to their Assist surface. Characters never join presence counts, speak into a room call or impersonate its members.

## Assist binding

**Existing foundation.** A component can seed a moqui.agent.AgentDefinition with an agentId, surfaces and instructionsLocation, and attach AgentToolPolicy rows. Dev AIDE does this for its dev agent. The Assist bootstrap lists agents offered to the current person. Starting a new conversation can select an agentId. Existing conversations retain their agent. Page suggestions already distinguish agent, path and record. [Dev agent seed](../../../dev/dev-aide/data/DevAideAgentData.xml) · [Assist interface](../../../../../docs/ai/Assist.md) · [Drawer agent selection](../../../base/webroot/screen/webroot/js/WebrootAssist.js)

**Proposed THREE binding.** Each station names a stable agentId of the form three- followed by the instruction directory name, for example three-proof-press. The matching component definition uses feature assist and instructionsLocation `component://mr-three/prompt/proof-press/AGENT.md`, varying the directory for each character. Each file is the actual role brief. Include it in the ordinary Assist instruction composition. A server-owned binding supplies the station, required accessible place, allowed context and agent ID. The caller cannot select an instructions path. Add the same named action to the world and directory, with drawer, chat and TUI surfaces as offered by the host. This design ships the curated files. The definitions, station bindings and agent-selection hook are later implementation work.

Selecting **Ask** first checks the station's zone and source access, then the user's offered agents and Assist availability. Open the chosen specialist in the normal Assist surface and focus its prompt. A greeting or suggested question appears without submitting a run. A different specialist starts its own conversation, preserving other conversations in history. Reopen a conversation only after checking the same viewer, agent and current scope. Revalidate the app, organization, facility, site and selected record on every read, including a conversation resumed outside the village. Use the owning app's authorized page or a small read adapter for the specific fields visible there. PASS work on another host uses its configured site authority. A missing adapter leaves the character able to give directions to the ordinary screen.

Make each cast member a guide with scoped read/navigation tools. Restrict reads and navigation to the intersection of the viewer’s grants and the agent’s role groups, as Assist does for screen tools. Explicit runtime tool policy and owning-service permissions enforce that role. A world grant confers no agent, record, write or payment capability. If Assist, the role file or the required site binding is unavailable, the station offers the neighboring real-screen action and a plain reason beside Ask. It never silently substitutes the generic agent.

**Paper check.** In Smithy, a contributor asks Proof Press about a request with no reported check. The local reply names that state and offers Checks. Across the glass a staff reviewer can independently ask about a different request, with a different conversation. At the quay the same contributor sees only the static hoist and cannot use Tallywheel through search. In the text directory a permitted warehouse worker can ask Tallywheel the same question as at the weighing pan, with no animation or audio.
